# 原生 PC 路线：静态重编译、兼容修复与交互

本文件用于选择原生 PC 路线后的实施。依据《科学超电磁炮》ULJS00354 汉化镜像的实测流程；它提供调查顺序和验证方法，不承诺任意 PSP ISO 都能自动移植。保留用户选择的原生目标；遇到兼容问题先定位并报告成本，不擅自把交付改成模拟器启动器。

## 1. 固定输入与分析基线

1. 为原 ISO 记录 SHA-256、大小、来源和版本，保持只读；在工作目录提取副本。先核对 `PARAM.SFO`、`UMD_DATA.BIN`、主程序和区域/汉化/DLC 差异，再复用他人的函数地址或资源工具。
2. 检查 `PSP_GAME/SYSDIR/EBOOT.BIN` 的真实格式、端序、架构、入口、加载段、section、导入和重定位。明文 ELF 可直接分析；不能因为另一份镜像可读，就假设当前输入也可读。无法解析时保留原文件并定位容器或工具能力，不伪造成功结果。
3. 输出机器可读分析摘要，至少包括加载段、内存范围、导入 NID、重定位数、未知指令和间接跳转风险。静态扫描出现未知指令不代表当前路径已执行；运行失败也不能只凭静态数量归因。
4. 对资源提取器先验证少量真实样本的头、尺寸、调色板、长度和边界，再批量提取。记录采用的实际解码入口，而不是仅照抄 README。

本作证据：EBOOT 为 ELF32 小端 MIPS PRX `0xffa0`，1,897,840 字节；2 个加载段、45,108 条重定位、263 个导入。扫描列出 12 个不支持编码，实测路径未证明执行到它们。GRP 有 2,335 个索引项，最初 12 个样本验证为 SHTXPS；研究代码旧 `decodeRLE` 已标为有错，实际入口为 `decodeRLE2`。这些数量和格式判断都属于本镜像，不能写成通用常量。

## 2. 锁定工具链并生成工程

静态重编译将 Allegrex 指令预先翻译成 C++，Refract 负责 PSP 系统、图形、音频和输入兼容；本案仍含解释器兜底。不要把生成结果称为原开发源码，也不要把“编译出 EXE”称为完整移植成功。

为工具源码固定 commit 或源 ZIP 的 SHA-256，记录本地补丁、编译器/CMake/Ninja 版本、目标架构、编译选项和依赖版本。旧项目原始 ZIP 无 commit 记录时，先记录现有 ZIP 哈希，不补造版本标识。工具安装放在工作区独立目录，使用任务脚本配置 PATH。

下列命令语法来自本案保存的 psprism `src/main.cpp` usage 和生成工程 README。它们是按阶段选择的独立示例，不是要求 init 后再重复 hydrate。运行前读取当前固定版本的 help/README，确认参数仍适用。变量均应绑定到当前任务的绝对路径；不要把占位符直接运行，也不要把 Visual Studio 的 `-A x64` 混进 Ninja 配置。

```powershell
# $psprism：固定版本的工具；$iso：已校验输入；$project：新的工程目录
& $psprism init $iso --display-name 'Game PC' --project-name game_native --output $project --extract-disc --yes
if ($LASTEXITCODE -ne 0) { throw '工程生成失败，先查看日志' }

# 从提取后的真实 ELF 做覆盖分析，保存输出用于后续比较
& $psprism (Join-Path $project 'disc/PSP_GAME/SYSDIR/EBOOT.BIN') --analyze

# 在已有干净导出工程里从相同输入生成私有树；--force 会重新生成，勿盲用
& $psprism hydrate --project $project --input $iso

# 以下为 README 的 Visual Studio x64 路线，需匹配的开发环境和依赖
& $cmake -S $project -B (Join-Path $project 'build/windows') -A x64
& $cmake --build (Join-Path $project 'build/windows') --config Release
```

本案实际使用 LLVM-MinGW 20261006 / Clang 23.1.3、CMake 4.4.4、Ninja 1.13.2；Release 采用 `-O1 -DNDEBUG`，`WINVER` 与 `_WIN32_WINNT` 为 `0x0A00`。这是历史复现配置，不是新项目必须照用的最新版本。工具构建脚本采用 CMake Ninja、显式 `CMAKE_CXX_COMPILER` 和 `CMAKE_MAKE_PROGRAM`；生成项目沿用相同编译器。7,199 个生成翻译文件合并为 56 个 unity 单元，这不等于恢复了 7,199 个原始函数。

本案为启动验证关闭 `REFRACT_USE_FFMPEG` 与 `REFRACT_DESKTOP_DIALOGS`，保留 Win32 消息框回退。关闭 FFmpeg 意味着 PMF 视频未启用，应写入限制；不能以缩包或启动成功为由宣布动画完整。正式补齐视频时选用与架构和构建方式匹配的库，再重新验证实际播放。

工程中区分：`original/` 原输入、`disc/` 提取资源、`src/generated/` 生成代码、`refract/` 兼容运行时、`patches/` 游戏专属补丁、`project.toml` 可复现元数据。通用运行时修复同时回写生成器模板与当前工程副本，避免重新 hydrate 后丢失。保持原始源码基线和可应用补丁；已应用补丁不要重复应用。

## 3. 以有界启动试验定位兼容缺口

按“加载完成 → 系统提示 → 标题 → 菜单 → 首段剧情 → 语音/视频 → 存档重启读取 → 特殊交互”推进。每次试验说明目标检查点、使用的 EXE/资源/存档版本和停止条件，设置日志大小、时间或帧数上限。先收集失败证据再修复，不无限重启或批量改动多个系统。

使用独立诊断 EXE、独立测试存档目录和独立日志。复用测试存档时记录来源，避免改动个人进度；共享同一存档目录的版本不要同时运行并保存。用户正在操作的窗口属于用户；用户说“我自己测试/先别动窗口”后停止激活、输入、截图与重启，继续离线分析。若用户授权独立诊断窗口，只操作已重新核对路径和身份的目标，不依赖旧 PID/窗口句柄。窗口消失先检查退出码、日志和用户操作事实，不直接称为崩溃或用户关闭。

| 观察到的失败 | 应采集的证据与修复方向 | 本案对应回归 |
| --- | --- | --- |
| 生成代码退回解释器后跳错地址 | 入口接受/拒绝、PC、待执行分支和延迟槽状态；保持跨执行方式的语义 | 分支加延迟槽后目标为 `0x08800278`，修复前误到 `0x0880026c`；测实际生成函数 |
| 线程反复创建后分配失败 | 请求栈大小、已分配范围、删除生命周期、空闲合并；失败时回滚栈/TLS | 请求 8 KiB 被扩大且删除未回收；实际分配器及 1,000 次创建/等待/删除循环 |
| 互斥锁缺失或阻塞 | guest workarea、owner、递归计数、争用、超时、删除；等待时释放执行令牌 | PSP SDK 快路径也修改 workarea，应以 guest 内存为权威；覆盖实际 HLE 的争用唤醒 |
| 文件读成功却报零字节 | 读取长度、线程退出状态、WaitThreadEnd/CB 返回链 | 保留正负退出值，不能统一返回零；覆盖真实 HLE 入口 |
| 音频反复载入 | 导入 NID、缓冲策略、调用频率、解码结果 | `sceAtracIsSecondBufferNeeded` 的全驻留路径；非零样本不等于人工听音通过 |
| 有 draw call 却看不到画面 | 真实顶点/UV/颜色/混合/深度和裁剪状态 | through 模式 Z 先截断再限幅到 0…65535，覆盖 NaN、无穷和边界 |
| 标题可见，剧情背景/人物全黑 | 实际 GE 指令流和提交数量，而非先重做素材 | 捕获 `BEZIER 0x05, arg=000404, vtype=80019f` 后才实现 2D through 三角曲面 |

GE 曲面实现需保留 PATCHDIVISION、曲面连接、位置/UV/RGBA 插值和地址推进规则。源顶点地址按控制点数推进，不能按细分输出数推进；限制顶点/内存上限。用索引与非索引、后继 PRIM、多曲面、数学中点和边界检查回归。本案只验证 2D through 三角曲面，不据此声称 3D/Spline 完整支持。

每个修复以真实失败输入建立最小复现，检查生产路径而非仅测试另写的模拟实现。比较修复前后 PC、返回值、字节或绘制提交；不要跳过内存异常、强行改游戏分支或把缺失接口一律返回成功来掩盖问题。参考其他实现前核对语义和许可，记录引用来源。

## 4. 保留原画质基线，再加入鼠标和阅读控制

先保存能交互的原画质 EXE、启动配置和测试证据，作为高清版回退与对照；它也可以成为原画质精简包的基础。鼠标、AUTO/SKIP 和高清贴图分开控制，避免用户只能通过大体积高清资源获得 PC 操作。

鼠标基线：滚轮改变高亮项、左键确认/推进、右键取消、中键 START，横向滚轮或 Shift+滚轮左右切换。明确这是按键映射；若用户要求直接点文字选菜单，应另做坐标命中并验证，不能把两者混称为“可点击”。

实现重点：

- 键盘、手柄、鼠标保持独立按下状态，再合并 PSP 按钮；释放鼠标不能释放键盘正在按住的同一按钮。
- 短按锁存直到控制器采样消费，不在每次渲染清除。测试按下与松开都落在两次采样之间的情况。
- 累积触控板小滚动增量，多格滚轮排队为独立按下/释放；测试横向滚动和节奏。
- 失焦/弹窗清理普通鼠标状态，防止卡键、穿透；弹窗关闭后的点击不得同时推进剧情。

AUTO/SKIP 优先接入已定位的游戏原生查询和文字/语音等待，不用连点确认模拟阅读，也不偷偷改写原游戏设置。保留原有按键行为；AUTO 与 SKIP 互斥，选择题、暂停/回看和系统弹窗取消，触发取消后需要释放当前手势再重新启动，避免跳过选项。

本案最终交互约定：鼠标开启 AUTO 或 SKIP 后切窗/最小化继续，状态指示常驻；Ctrl 临时 SKIP 仅在前台按住生效，松开或失焦清除。普通对白窗口的状态变化不应使 AUTO 闪烁或取消。用状态机、实际 Win32 消息路径和生产 hook 三层回归覆盖这些条件，再进行真正的最小化/恢复场景检查。

**游戏专属定位不可直接复用：** 本案 SKIP 查询 `0x53b04`、生命周期 `0x58b34`、第二加载段偏移 `0x16d800` 及相关 flags/window/choice/special 地址，只对已核对的该版镜像成立。先区分 image offset、绝对 guest 地址、段相对立即数，验证导入/重定位/反汇编与运行中值；地址算错也可能读到“看似合理”的零值。每个游戏和补丁版本重新定位，记录原函数行为与 hook 前提。

## 5. 把测试范围写进交付结论

逐项记录“离线检查通过、定向回归通过、实际窗口已观察、用户已验收、未测试”。截图标明真实运行帧、生产着色器离屏 fixture 或离线合成；后两者不能冒充游戏实机。首段剧情可见不证明通关；启动存档创建成功不证明剧情保存/读取；非零音频样本不证明音画同步。

移交打包前至少保留：输入/工具/补丁哈希，配置与构建日志，当前 EXE 对应源码，生产回归结果，实际可玩路径，未解决项，以及原画质回退入口。EXE 还依赖 `guest_image.bin`、`relocations.bin`、运行库 DLL 和 disc/ISO 资源；单独复制 EXE 不是便携包。后续进入素材处理与发布验证参考，不在此阶段删除剧情、语音或未验证的媒体资源。

本案已知边界包括 FFmpeg 关闭、有限的回调/流式音频验证、未证实 DLC 可用、未全剧情/小游戏/通关验收。遇到 NPDRM 未实现或可选 DLC 文件缺失，应如实报告实际分支与错误，不伪造验证通过。公开工程的元数据/补丁与含游戏代码、原图、ISO 的私有生成树分开管理；框架许可证不自动授权游戏内容。
